16"""encrypt secret setting overrides 

17 

18Revision ID: e4b3754984d8 

19Revises: c9880f0ac1bd 

20Create Date: 2026-09-04 18:41:55.073171 

21 

22Re-encrypt the secret-typed leaves of every ``settingoverride`` row this track 

23can resolve, which the write path stored in the clear before this release. 

24 

25The settings classes are passed in rather than discovered: resolving them 

26through ``build_sep_override_proxies()`` would import app packages, and every 

27app ``__init__`` pulls a route graph with a cycle the migration cannot survive. 

28 

29The list below is complete because no *overridable* field reaches a secret 

30outside these classes. An app-owned class can be secret-bearing 

31(``HealthReportSettings.api_key`` is), but every such field today is 

32``NOT_OVERRIDABLE``, so it can never produce an override row to re-encrypt. 

33``test_migration_settings_classes_cover_every_secret_bearing_class`` holds that 

34invariant from the test side, where the registry *can* be imported. 

35 

36Completeness is claimed as of this revision only. Alembic never re-runs an 

37applied revision, so a deployment already carrying this one is not covered by it 

38when a field it did not reach turns up later — a secret-bearing class becoming 

39overridable, or a plain field being retyped to a secret. Rows written for such a 

40field before the change stay in the clear until a new data migration rewrites 

41them. 

42 

43Downgrade restores the plaintext the previous release reads. 

44"""
