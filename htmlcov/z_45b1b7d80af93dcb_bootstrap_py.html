16"""Create the Celery beat schedule tables ahead of the processes that read them. 

17 

18The ``sqlalchemy_celery_beat`` tables are created by no alembic revision in any of 

19PMM Extensions' three migration tracks: the library builds them itself, from 

20:meth:`sqlalchemy_celery_beat.session.SessionManager.prepare_models`, which 

21:class:`~sqlalchemy_celery_beat.schedulers.DatabaseScheduler` reaches on beat's 

22own startup. Every service that seeds periodic tasks during its lifespan 

23(:func:`app.core.celery.utils.init_periodic_tasks_db`) therefore reads tables 

24whose only creator is a process ordered *behind* it, and on a database with no 

25schema the read fails. 

26 

27Driving the library's own bootstrap from a step ordered ahead of those services 

28breaks the cycle while leaving the tables the library's to define — nothing here 

29declares their shape. This module is kept beside :mod:`app.core.celery.db` rather 

30than inside it so importing it does not construct that module's asynchronous 

31engine, which resolves the same setting through a driver 

32:meth:`~sqlalchemy_celery_beat.session.SessionManager.prepare_models` cannot use. 

33"""

55def _wait_for_store(engine: Engine) -> None: 

56 """Block until the beat store accepts a connection. 

57 

58 The side-car's three alembic one-shots wait on ``EXTENSIONS_DB_HOST``/``EXTENSIONS_DB_PORT`` 

59 in the shell, because that is the database they upgrade. The beat store is 

60 whatever ``CELERY.beat_dburi`` resolves to, and a deployment may point it at a 

61 separate database, so readiness is probed against the URL this process will 

62 actually dial rather than against a host named in the program table. 

63 

64 The wait is unbounded, matching those three shell loops. A bounded one could 

65 expire while the store was merely slow, and the caller runs as a one-shot that 

66 is never re-run, so its sentinel could then never appear — leaving every 

67 program gated on it waiting for the life of the container. What bounds the 

68 observable behaviour instead is the gate in front of each API program, and the 

69 healthcheck, which reports the missing sentinel either way. 

70 

71 ``prepare_models`` retries too, but only for the check-then-create race it was 

72 written for: ten attempts with sub-second backoff, which a database that has 

73 not finished starting outlasts. 

74 

75 :param engine: The synchronous engine for the resolved beat store. 

76 :raises DBAPIError: On a connection failure that is not an 

77 ``OperationalError``, which is raised on the first attempt rather than 

78 retried — only an ``OperationalError`` is treated as "not up yet". 

79 """ 

80 while True: 

81 try: 

82 with engine.connect(): 

83 return 

84 except OperationalError: 

85 # Host and port only: the resolved URL carries the store's password. 

86 logger.info( 

87 "Waiting for the Celery beat store at %s:%s", 

88 engine.url.host, 

89 engine.url.port, 

90 ) 

91 sleep(STORE_READINESS_POLL_INTERVAL)

111def _has_run(row: PeriodicTask) -> bool: 

112 """Return whether beat has fired a schedule since it was stored. 

113 

114 :param row: The stored schedule. 

115 :return: Whether it has a recorded run. 

116 """ 

117 return bool(row.total_run_count) or row.last_run_at is not None

120def _move_task_path(value: object) -> object: 

121 """Move every string that starts with the pre-rename package to the new one. 

122 

123 Only a value that *starts* with the package's dotted path is a path under 

124 it; a key, or a string that merely contains the text, is left as stored. 

125 

126 :param value: A decoded JSON value. 

127 :return: The value with each such string moved, or the value itself. 

128 """ 

129 if isinstance(value, str) and value.startswith(PRE_RENAME_TASK_PREFIX): 

130 return TASK_PREFIX + value.removeprefix(PRE_RENAME_TASK_PREFIX) 

131 if isinstance(value, dict): 

132 return {key: _move_task_path(item) for key, item in value.items()} 

133 if isinstance(value, list): 

134 return [_move_task_path(item) for item in value] 

135 return value

138def _moved_kwargs(kwargs: str) -> str | None: 

139 """Return a row's JSON keyword arguments with their task paths moved. 

140 

141 :param kwargs: The stored keyword arguments, a JSON object. 

142 :return: The rewritten JSON, or ``None`` when nothing in it moves. 

143 """ 

144 if PRE_RENAME_TASK_PREFIX not in kwargs: 

145 return None 

146 try: 

147 decoded = json.loads(kwargs) 

148 except ValueError: 

149 logger.warning("Left a Celery beat schedule's unparsable kwargs as stored.") 

150 return None 

151 moved = _move_task_path(decoded) 

152 return json.dumps(moved) if moved != decoded else None

155def move_pre_rename_periodic_tasks(session_factory: sessionmaker[Session]) -> int: 

156 """Move stored schedules forward from their pre-rename names and task paths. 

157 

158 A beat row stores the schedule's name, seeded under a prefix, the dotted 

159 path of the task it fires, a module path under the package, and keyword 

160 arguments that can name another such path, such as the syncer an inventory 

161 sync is pinned to. The rename moved all three. Seeding reconciles only rows 

162 under the current prefix, so a row left under the old one would keep firing 

163 a task path that no longer resolves, alongside the new row seeded beside it. 

164 Renaming the row in place keeps its schedule state instead. 

165 

166 A row whose new name is already stored is resolved by run state. When the 

167 stored row has never fired, it is a fresh seed and gives way, so the old 

168 row's configuration, ``enabled`` choice and run count carry forward. When 

169 both have fired, neither can be dropped without losing an operator's state, 

170 and the step fails instead. 

171 

172 The rows are changed through the ORM, so the library's change listener tells 

173 a running scheduler to reload. Every later run finds nothing to move. 

174 

175 :param session_factory: Sessions bound to the resolved beat store. 

176 :return: How many rows were moved. 

177 :raises PreRenameScheduleConflictError: When a schedule stored under both 

178 names has fired under both. 

179 """ 

180 with session_factory() as session: 

181 stale = ( 

182 session.query(PeriodicTask) 

183 .filter( 

184 or_( 

185 PeriodicTask.name.startswith( 

186 PRE_RENAME_NAME_PREFIX, autoescape=True 

187 ), 

188 PeriodicTask.task.startswith( 

189 PRE_RENAME_TASK_PREFIX, autoescape=True 

190 ), 

191 PeriodicTask.kwargs.contains( 

192 PRE_RENAME_TASK_PREFIX, autoescape=True 

193 ), 

194 ) 

195 ) 

196 .all() 

197 ) 

198 moved = 0 

199 for row in stale: 

200 if inspect(row).deleted: 200 ↛ 201line 200 didn't jump to line 201 because the condition on line 200 was never true

201 continue 

202 changed = False 

203 if row.name.startswith(PRE_RENAME_NAME_PREFIX): 

204 name = NAME_PREFIX + row.name.removeprefix(PRE_RENAME_NAME_PREFIX) 

205 current = session.query(PeriodicTask).filter_by(name=name).one_or_none() 

206 if current is not None: 

207 if _has_run(current): 

208 raise PreRenameScheduleConflictError( 

209 f"Celery beat schedules {row.name!r} and {name!r} have " 

210 "both fired; delete the one to discard, then rerun." 

211 ) 

212 session.delete(current) 

213 session.flush() 

214 row.name = name 

215 changed = True 

216 if row.task.startswith(PRE_RENAME_TASK_PREFIX): 

217 row.task = TASK_PREFIX + row.task.removeprefix(PRE_RENAME_TASK_PREFIX) 

218 changed = True 

219 if row.kwargs and (kwargs := _moved_kwargs(str(row.kwargs))) is not None: 

220 row.kwargs = kwargs # ty: ignore[invalid-assignment] 

221 changed = True 

222 moved += changed 

223 session.commit() 

224 if moved: 

225 logger.info("Moved %d Celery beat schedules to their renamed names.", moved) 

226 return moved

229def bootstrap_beat_schema() -> None: 

230 """Create the ``sqlalchemy_celery_beat`` schedule tables if they are absent. 

231 

232 Then move any schedule stored under its pre-rename name forward, through 

233 :func:`move_pre_rename_periodic_tasks`, before a seeding service reads it. 

234 

235 The store and schema are resolved exactly as 

236 :meth:`sqlalchemy_celery_beat.schedulers.DatabaseScheduler.__init__` resolves 

237 them, so beat and this step cannot disagree about where the tables belong. 

238 ``prepare_models`` checks before it creates, so a store that already carries 

239 them is left alone. 

240 

241 The scheduler's pool options are deliberately **not** forwarded. On this 

242 non-forked path the library pins ``NullPool`` and drops every 

243 ``pool``-prefixed key, so such an option is either ignored or — for a key 

244 outside that prefix, such as ``max_overflow`` — rejected outright by 

245 ``create_engine``. Neither outcome can configure anything, and the second 

246 would fail this step on a documented, validated setting. 

247 

248 :raises DBAPIError: When the store refuses a connection for a reason other 

249 than not being up yet, or when creating the tables fails after the 

250 library has exhausted its own retries. The family is ``DBAPIError`` 

251 rather than ``DatabaseError`` because the first case surfaces as 

252 ``InterfaceError``, a sibling of ``DatabaseError`` rather than one of 

253 its subclasses. 

254 :raises ArgumentError: When the resolved URL is malformed, or names a dialect 

255 whose driver is not installed. The engine is built before the wait, so 

256 this surfaces immediately. 

257 """ 

258 manager = SessionManager() 

259 engine, session_factory = manager.create_session( 

260 settings.CELERY.beat_dburi, 

261 schema=settings.CELERY.beat_schema, 

262 ) 

263 try: 

264 _wait_for_store(engine) 

265 manager.prepare_models(engine, schema=settings.CELERY.beat_schema) 

266 move_pre_rename_periodic_tasks(session_factory) 

267 finally: 

268 engine.dispose()

271def main() -> None: 

272 """Run the bootstrap, configuring logging for a freshly spawned process. 

273 

274 Supervisord starts this in a process that has run no ``dictConfig``, and the 

275 wait's own log lines are the only account an operator gets of why the schema 

276 step has not finished. A failure is deliberately left to propagate: the 

277 non-zero exit is what keeps the caller's sentinel unwritten. 

278 

279 :raises SQLAlchemyError: When the tables cannot be created, or the store 

280 refuses a connection for a reason other than not being up yet. 

281 """ 

282 logging.config.dictConfig(settings.LOGGING_CONFIG) 

283 bootstrap_beat_schema() 

284 logger.info("Celery beat schedule tables are present.")
