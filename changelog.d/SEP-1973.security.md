Secret-typed settings-override values are now encrypted at rest, and one migration per Alembic track re-encrypts rows written before this release. A password embedded in a URL-typed setting is not covered and is still stored in the clear, even though it is redacted wherever the API renders it. Rolling back to an earlier release requires running those migrations' downgrade first, and an override the configured `ENCRYPTION_KEY` cannot decrypt is skipped so the setting falls back to its YAML/env value.
