Retired inventory nodes, services, schemas and tables are now permanently deleted once they have been retired for `SEP.INVENTORY.COLLECTION_RETENTION` (30 days by default) and nothing SEP persisted still resolves them — no backup-catalog run, task envelope, in-flight execution or Celery-beat schedule. Deletion is irreversible and cascades to the entity's subtree and observation rows, so the job stays off unless `TASKS__INVENTORY_COLLECTION_INTERVAL` is set — an environment variable read at startup, so it takes effect on restart and cannot be changed from the settings admin UI. The PMM-embedded profile ships it as `1 days`.
