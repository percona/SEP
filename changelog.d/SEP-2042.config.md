The PMM side-car's Celery worker now starts 4 prefork processes instead of one per host CPU, bounding its PostgreSQL connections, and its baked settings pin every service's database pool at 3 connections plus 2 overflow with a 10-second timeout. Both take effect when the container is recreated from a new image. Set CELERY__WORKER_CONCURRENCY to change the worker count, which is now read as an integer. A bind-mounted settings.yaml keeps whatever it sets, and standalone deployments are unchanged.
