The PMM side-car's Celery worker now starts 4 prefork processes instead of one per host CPU, bounding the PostgreSQL connections it can hold; this takes effect when the container is recreated from a new image. Its baked settings also pin the database pool at the current defaults of 3 connections plus 2 overflow with a 10-second timeout, so that a later change to those defaults cannot move the side-car's budget — no pool sizing changes today. Set CELERY__WORKER_CONCURRENCY to change the worker count, which is now read as an integer instead of failing the worker at startup. A bind-mounted settings.yaml keeps whatever it sets, and standalone deployments are unchanged.
