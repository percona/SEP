PostgreSQL-backed deployments no longer exhaust the database server's connection limit under normal concurrent use, which intermittently returned HTTP 500 across all three sub-applications. Each API engine now defaults to POOL_SIZE=3, MAX_OVERFLOW=2 and POOL_TIMEOUT=10.0 instead of SQLAlchemy's 5, 10 and 30, and a database capacity refusal now returns HTTP 503 rather than 500. SQLite deployments keep the engine they build today; the pool settings are ignored there, so an install that had set one against SQLite no longer has it applied. A deployment that configured only one of the three pool settings now inherits the new defaults for the other two, so set them explicitly to keep the previous values.
