Settings-override secrets written from this release carry an explicit `sep.enc.v1.` envelope marker at rest, so whether a stored value is already encrypted is read off its own format instead of inferred from the text — closing a case where an operator-chosen token that happened to look like ciphertext was skipped by the encryption migration and left in the clear. Rows written before this release carry no marker, keep decrypting unchanged, and are never rewritten, so there is no migration to run and nothing to do on upgrade. Rolling the code back to an earlier release does require a downgrade first, because that release reads a marked value as plaintext and would present it to a remote as a credential: `alembic --name inventory downgrade -1`, `alembic --name tasks downgrade -1`, and `alembic --name sep downgrade sep_main@-1` — the `sep` track carries several branch heads, so a bare `-1` there downgrades an arbitrary one of them. Each step only strips the marker: it needs no `ENCRYPTION_KEY`, decrypts nothing, and leaves the values encrypted, so it is safe to run on a deployment whose key has been rotated away.
