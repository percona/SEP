The installer now serves the React SPA by default on new installs and installer re-runs; existing installations keep their rendered configuration until the installer is run against them again, and `SEP_SERVE_FRONTEND=0` still restores the legacy Jinja UI. Nginx now also proxies `/artifacts/` to the backend, so the signed artifact-download URLs handed to remote script executors keep resolving when the SPA is served, and every backend-proxied path now takes precedence over the SPA's static-asset rule, so a proxied file whose name ends in a web-asset extension is no longer served from the bundle instead of the backend. The new default requires a SEP image that carries the React bundle at `/home/sep/app/frontend/dist`; the installer now verifies this straight after pulling the image and stops with guidance when the bundle is absent, instead of leaving nginx stuck behind a failing `frontend-init` step.
