A task name is refused with HTTP 422 unless it is a single plain URL path segment, applied wherever SEP composes a task name into a request to the Tasks service, so a name carrying URL syntax can no longer reshape that request. The same check now runs before a task is created or renamed, so a name that no later request could address is refused instead of stored — a task group is rejected before its first task is created, rather than part-created and left behind by a rollback that cannot address it.
