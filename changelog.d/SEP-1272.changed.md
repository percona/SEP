Runtime app state now models a four-state lifecycle (`ENABLED`, `ENABLING`, `DISABLED`, `DISABLING`). The admin `PUT /api/admin/apps/{app_key}/state` accepts `{"lifecycle_state": "<state>"}` and enforces the allowed transition edges (illegal transitions return HTTP 409), the admin listing reports `lifecycle_state` alongside the derived `enabled` flag, and the per-router guard returns HTTP 503 for any non-`ENABLED` state. The transitional states give a future drain framework an observable window before an app goes fully offline.
