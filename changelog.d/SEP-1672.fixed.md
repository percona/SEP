An XtraBackup job using the `fast_restore` incremental method against an encrypted base backup now reports the real reason it falls back to a full backup: the run log names the encrypted base instead of blaming a compressed one. Both encryption formats are detected regardless of whether the job still has encryption enabled. Behaviour is otherwise unchanged — such a job already produced a full backup on every run, and `less_space` incremental chains against an encrypted base keep working as before.
