An XtraBackup job using the `fast_restore` incremental method against an encrypted base backup now reports the real reason it falls back to a full backup: the run log names the encrypted base instead of blaming a compressed one. Both encryption formats are detected regardless of whether the job still has encryption enabled, and a base left only partly encrypted by an interrupted encryption pass is now caught too — previously such a base could start an incremental that could not be merged. `less_space` incremental chains against an encrypted base keep working as before.
