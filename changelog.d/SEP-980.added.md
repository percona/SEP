Database-backed runtime overrides for a curated set of hot-reloadable SEP configuration fields. SEP and Tasks API processes refresh their snapshot every SETTINGS_OVERRIDE_REFRESH_INTERVAL (default 30s) and the new value takes effect on the next read. Override rows live in the per-service `settingoverride` table; the admin REST API for managing them ships in SEP-981 (a follow-up). Until then operators with direct DB access can write rows manually, but must populate `created_at` (e.g. `CURRENT_TIMESTAMP`) and `is_active` -- both columns are `NOT NULL` without a server default. The `setting_class` column accepts the `SettingClassEnum` member names (NOT the Pydantic class names): `SEP_SETTINGS`, `TASKS_SETTINGS`, `SNIPPETS_SETTINGS`, `MESSAGES_SETTINGS`. HOT fields per class in this release: `SEP_SETTINGS` covers `CONNECTIVITY_CHECK_DEFAULT`, `ARTIFACT_DOWNLOAD_TTL`, `SYNC_REFRESH_TIME`; `TASKS_SETTINGS` covers `PRE_EXECUTION_CONNECTIVITY_CHECK`, `STALENESS_THRESHOLD_SECONDS`; `SNIPPETS_SETTINGS` covers `ENABLE_MANUAL_SYNC`, `PREVIEW_MAX_CHARS`, `PREVIEW_MAX_LINES`; `MESSAGES_SETTINGS` covers `LEVEL`. Inventory has no HOT fields and skips the refresher. Inventory/Tasks API endpoints, PMM endpoint, Celery-side fields, and snippets sync interval are intentionally NOT_OVERRIDABLE -- they are baked into long-lived objects that the snapshot refresh cannot reach without follow-up work tracked in SEP-1037 / SEP-1038 / SEP-1039.
