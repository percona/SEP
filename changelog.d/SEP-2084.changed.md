Run-form labels and help text across the builtin diagnostic scripts now describe what each field is for, rather than naming the command-line flag behind it.
The six log extractors' Issue Time field is now a date-time picker instead of a free-text box, so it accepts minute precision where the text box accepted seconds. The value is read in the executor host's time zone: a timestamp submitted through the JSON execute API with an explicit UTC offset is now converted to UTC and the offset dropped, where it previously reached the script intact.
The `postgresql_pg_gather` and `postgresql_query_tuning` run forms now show a Port field, which invalid front matter had been suppressing entirely.
Minutes on five of the log extractors, and Target database on `postgresql_pg_gather`, are now optional: a submission that omits them runs with 30 minutes and the `postgres` database respectively, where it was previously rejected.
The `time_drift_check` script now carries a description in the script list and in search results; a misspelled front-matter key had been dropping it.
