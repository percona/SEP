MongoDB backups now reject an incomplete, malformed, or cross-wired per-task S3 storage config at create time (bucket/region required and well-formed, endpoint URL validated, filesystem/S3 fields no longer silently ignored). The configured storage is applied to PBM before each logical/physical backup, so backups land in the specified bucket instead of PBM cluster-wide storage. Existing MongoDB backup tasks whose per-task S3 storage was incomplete or unreachable now fail with an explicit storage error instead of silently backing up to PBM's cluster-wide storage; re-check the Storage section on existing tasks after upgrading.
