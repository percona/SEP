Diagnostics delivery gains `SEP.DIAGNOSTICS_DELIVERY_INPUTS`, an API-overridable key carrying the receiver endpoint and the values of the secrets the configured delivery plan declares, so delivery can be turned on without editing a settings file or restarting; it is written as one whole-object PATCH naming exactly the plan's declared secret names, and per-leaf writes are refused. The Send action becomes available as soon as the write lands, but background workers pick the new values up only on their next override refresh (`SETTINGS_OVERRIDE_REFRESH_INTERVAL`, 30 seconds by default), so a send started within that window can still fail as unconfigured; retry it once the interval has elapsed. The PMM side-car image now bakes a delivery plan pointing at Percona's production ServiceNow (`percona.service-now.com`) with its credentials empty and allowlists the new key, so no bundle is sent until an operator supplies them; a standalone deployment ships no plan and is unaffected until one is configured.
