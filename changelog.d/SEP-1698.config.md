Diagnostics delivery gains `SEP.DIAGNOSTICS_DELIVERY_INPUTS`, an API-overridable key carrying the receiver endpoint and the values of the secrets the configured delivery plan declares, so delivery can be turned on without editing a settings file or restarting; it is written as one whole-object PATCH naming exactly the plan's declared secret names, and per-leaf writes are refused. The Send action becomes available as soon as the write lands, and a send that would otherwise report delivery as unconfigured re-reads the stored values before failing, so turning delivery on takes effect for sends enqueued straight afterwards; changing an already-working plan still waits for a worker's own refresh, which has no fixed upper bound, so sends enqueued in the meantime deliver against the previous values. The PMM side-car image now bakes a delivery plan pointing at Percona's production ServiceNow (`percona.service-now.com`) with its credentials empty and allowlists the new key, so no bundle is sent until an operator supplies them; a standalone deployment ships no plan and is unaffected until one is configured.
