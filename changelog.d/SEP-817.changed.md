Move task logs out of `execution_request.tracking.task_logs` into a dedicated append-only `taskhistory_log` table; legacy records continue to render via a dual-read fallback until their eventual cleanup. The `tracking.task_logs` field is no longer populated for new task histories and is no longer collapsed to a boolean in `TaskHistoryResponse` for pre-migration records — API consumers that relied on the field's presence should switch to streaming the `/history/{id}/logs/` endpoint.
