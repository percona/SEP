A MySQL restore that names an AES-256 key file without declaring an AES-256 encryption format, or that declares AES-256 or dual encryption for a Mydumper or Binlog restore, is now rejected with a 422 instead of being accepted. API clients posting either shape have to declare the encryption format that matches the backup they are restoring; stored restores carrying the old shape are repaired when the edit form is served, so no existing task is left unopenable.
