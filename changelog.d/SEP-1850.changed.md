Every unsafe API route (POST, PUT, PATCH, DELETE) now resolves to an explicit minimum role instead of one shared administrator flag: `POST /restore` and `POST /push` in Alert Templates admit an `editor`, the batch read at `POST /api/tasks/history/latest` admits any authenticated caller as before, and every other unsafe route in SEP, inventory and tasks requires an `admin` — which is also what a route with no recorded decision takes, so a newly added route stays administrator-only. Reads are unchanged. Whether a deployment sees any difference depends on the auth provider: Casdoor exposes no role concept and yields only `admin` or `viewer`, so Casdoor deployments behave exactly as before, and the PMM-embedded side-car ships `inventory`, `atw` and `mysql_backups`, all of which remain `admin`. No new configuration is required. Out-of-tree app packages that import the gate directly must rename `require_admin_for_unsafe_methods` / `RequireAdminForUnsafeMethods` to `require_minimum_role_for_unsafe_methods` / `RequireMinimumRoleForUnsafeMethods`, and replace `allow_non_admin_mutation` with `require_minimum_role(UserRole.NONE)`.
