A snippet whose frontmatter declares a blank `title` or `description` no longer fails the Snippet Manager list, the alert-troubleshooting detail view, the snippet approval response, or the per-snippet form schema. The blank value now falls back to the filename (or an empty description) the same way an omitted key always has, so one malformed snippet can no longer break a page for every other snippet on it. A non-text value such as `title: 5` is shown as text for the same reason.
