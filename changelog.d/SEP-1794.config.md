SEP can now be served under a URL prefix: the new `SEP.ROOT_PATH` setting defaults to `""` so existing deployments are unchanged, while the PMM side-car image ships it as `/sep`. When a prefix is configured, `BASE_URL` and `SNIPPETS_BASE_URL` must already include it, because artifact download URLs are now joined onto their path instead of replacing it — an existing side-car setting `BASE_URL=https://host` must become `https://host/sep`. SEP warns at startup, and again where the URL is built, rather than refusing to start. `SESSION_REFRESH.PATH` stays stated relative to the application root and is anchored under the prefix when the cookie is emitted, so it needs no change.
