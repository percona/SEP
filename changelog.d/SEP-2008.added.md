The app schema and the task execute response now carry the state a client needs to poll a run to completion: every GET /api/apps/<app>/schema for a task-style app declares a task_statuses vocabulary marking which of the eight status values end a run, and POST /{task_name}/execute returns the dispatched run's status and created_at alongside task_name and task_id. Both are additive, and reach all eight derived execute routes at once because they ship in the shared framework rather than per app; an app declaring entities omits task_statuses.
