Task-style app schemas and task execute responses now publish the run state a client needs to poll a run to completion. `GET /api/apps/{app}/schema` gains a `task_statuses` list declaring, per status value, whether it ends a run, and `POST /api/apps/{app}/{task_name}/execute` returns the dispatched run's `status` and `created_at` alongside the existing `task_name` and `task_id`. Both additions ship in the shared framework, so all eight derived execute routes gain the fields at once; an app declaring `entities` omits `task_statuses`.
