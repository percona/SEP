Offset/limit pagination is now centralized in `app.core.pagination`: `limit=0` no longer means "fetch all", list endpoints require `limit>=1`, and `limit>200` is rejected with 422 on all shared paginated list routes (inventory, tasks, SEP gateway, etc.)—only merged task-history enforced this cap before, so integrators sending e.g. `limit=500` to `/api/inventory/` will now get 422; send explicit bounded `offset`/`limit` and iterate pages for full traversal. MySQL backups list keeps its separate `limit<=50` cap via `make_pagination_dep`.
